# 领域规则

本文档定义了健身训练应用中必须遵守的业务规则和约束。这些规则确保系统的输出符合健身领域的专业标准和用户安全。

## 核心原则

### 1. 知识资料不等于个人事实

**规则:** 从健身视频或文档中提取的信息属于通用知识，不能自动成为用户的个人确认事实。

**实现:**
- 知识库内容存储在 `knowledge_chunks` 表
- 用户个人事实存储在 `profile_facts` 表
- 两者严格分离，需要用户明确确认才能转换

**示例:**
- ✅ 正确: "视频中提到肩胛骨灵活性训练方法" (知识)
- ❌ 错误: "用户的肩胛骨不够灵活" (未经确认的推断)

### 2. 计划目标不等于实际完成

**规则:** 训练计划中设定的目标(组数、次数、重量)与用户实际完成的训练记录必须分开存储和追踪。

**实现:**
- 计划存储在 `plan_versions` 表的 JSONB 字段
- 实际记录存储在 `workout_sessions`, `session_exercises`, `workout_sets` 表
- 统计时使用实际记录，不假设计划已完成

**示例:**
- ✅ 正确: 计划要求 3x10 深蹲，实际记录 3x8
- ❌ 错误: 未记录但假设已按计划完成

### 3. 未记录不等于没有训练

**规则:** 用户可能在离线或其他情况下进行了训练但未记录。系统不应假设缺少记录就等于没有训练。

**实现:**
- 统计时明确标注数据范围
- 周复盘时如果数据不足，返回"数据不足以生成复盘"
- 不从缺失数据推断退步

**示例:**
- ✅ 正确: "本周已记录 2 次训练"
- ❌ 错误: "本周只训练了 2 次" (可能有未记录的)

### 4. 模型推断不等于用户已确认事实

**规则:** AI 模型生成的任何推断、建议或判断必须由用户明确确认后才能成为系统中的事实。

**实现:**
- 模型输出保存为 `memory_candidates` (status=pending)
- 用户确认后才写入 `profile_facts`
- `profile_facts` 包含 `source` 字段标记来源

**允许的来源:**
- `user_statement`: 用户直接陈述
- `reported_professional_advice`: 用户转述的专业建议(需标注不确定性)

**禁止的来源:**
- 模型自主推断
- 健身博主视频内容(属于知识，不是个人事实)
- 第三方未确认的转述

### 5. 生成合法 JSON 不等于建议正确

**规则:** 模型输出通过 Pydantic 验证只能保证格式正确，不能保证内容符合领域规则。

**实现:**
- 两层验证: Pydantic Schema + 领域规则函数
- 领域验证检查:
  - 动作和模板存在且已审核
  - 器械匹配用户可用器械
  - 训练量符合模板范围
  - 不包含用户排除的动作
  - 负重值基于实际记录，不虚构

**示例:**
- ✅ 通过验证: JSON 格式正确 + 所有动作已审核 + 器械匹配
- ❌ 拒绝: JSON 格式正确但包含用户不可用的器械

### 6. 有引用不等于引用支持该结论

**规则:** 模型生成的建议可能包含引用 ID，但必须验证引用内容确实支持该结论。

**实现:**
- 引用验证函数检查引用内容
- 人工抽查: 目标 ≥95% 引用支持率
- 不符合的建议需要修正或移除引用

**示例:**
- ✅ 正确: 建议深蹲配重进阶，引用用户最近两次深蹲记录
- ❌ 错误: 建议增加训练频率，引用的是关于饮食的视频

### 7. 本地缓存不等于备份

**规则:** IndexedDB 中的离线数据仅为临时缓存，不能作为数据恢复的依据。

**实现:**
- 离线数据必须同步到服务器
- 定期加密备份服务器数据到独立存储
- 本地 Windows PC 下载备份副本
- 浏览器数据可能被清除，不可依赖

### 8. 使用模型 API 不等于无需业务数据库

**规则:** 虽然调用大模型 API，但业务数据、训练记录、用户档案必须存储在自己的数据库中。

**实现:**
- PostgreSQL 存储所有业务事实
- 模型 API 仅用于生成建议
- 对话历史保留 90 天，但确认的事实永久保留在 `profile_facts`
- 模型更换不影响历史数据完整性

## 训练计划约束

### 1. 计划生成前置条件

必须满足以下条件才能生成计划:

- [ ] 用户已完成档案 (目标、经验、器械、时间)
- [ ] 至少有 1 个已审核的训练模板匹配用户条件
- [ ] 模板要求的动作已审核且用户可执行
- [ ] 没有未解决的不适报告

### 2. 计划必须包含

- 明确的训练天数 (与模板一致)
- 每个动作的组数、次数/时长、休息时间
- 负重模式 (外部总重、单侧、自重、辅助、弹力带)
- 组类型 (热身组、工作组)
- 动作 ID 和模板 ID (可追溯)

### 3. 计划约束验证

生成的计划必须通过以下验证:

```python
def validate_plan_constraints(plan, profile, template):
    # 1. 动作和模板存在且已审核
    assert all(exercise.reviewed for exercise in plan.exercises)
    assert template.reviewed
    
    # 2. 器械匹配
    for exercise in plan.exercises:
        assert exercise.equipment in profile.available_equipment
    
    # 3. 训练天数匹配
    assert len(plan.training_days) == template.sessions_per_week
    
    # 4. 训练量在模板范围内
    for session in plan.sessions:
        assert template.min_sets <= session.total_sets <= template.max_sets
        assert template.min_duration <= session.duration <= template.max_duration
    
    # 5. 不包含排除的动作
    excluded = profile.excluded_exercises
    assert not any(ex.id in excluded for ex in plan.exercises)
    
    # 6. 基础版本记录完整
    assert plan.basis_profile_version == profile.version
    assert plan.basis_template_version == template.version
    
    return True
```

## 进阶规则

### Double Progression V1

该规则用于判断是否可以增加负重或次数。必须满足:

1. **同一动作版本**: 不能跨动作版本对比
2. **可比器械和负重模式**: 杠铃和哑铃不直接对比
3. **最近 2 次会话数据**: 数据必须完整且有效
4. **完成目标次数**: 所有工作组达到目标次数下限
5. **可接受的 RIR**: RIR ≤ 模板允许的最大 RIR
6. **无未解决不适**: 该动作相关的不适已解决或排除
7. **明确的可用增量**: 0.5kg/1kg/2.5kg 取决于器械
8. **保持在模板范围内**: 增量后仍在模板的组数和次数范围内

**输出**: 结构化建议，不直接写入数据库，需要用户采用。

## 记忆管理规则

### 允许保存为 profile_facts 的来源

1. **用户直接陈述** (`source=user_statement`)
   - "我左膝盖做深蹲时不舒服"
   - "我每周只能训练 3 天"
   - "我家里有哑铃和引体向上杆"

2. **用户转述专业建议** (`source=reported_professional_advice`)
   - "理疗师说我需要加强髋关节灵活性"
   - 必须标注: 来源、时间、确定性级别

### 禁止保存为 profile_facts 的来源

1. AI 模型的推断
2. 健身视频或文档的通用建议
3. 未经用户确认的第三方评价
4. 从不完整训练记录推断的"能力"

### 记忆冲突处理

当新记忆与已有记忆冲突:

1. 提取新记忆候选
2. 检测冲突 (同一 `kind` 字段)
3. 提示用户确认:
   - 保留旧记忆
   - 替换为新记忆
   - 标记旧记忆为"已过时"但保留
4. 更新 `planning_revision` 触发重新生成计划

## 安全原则

### 医疗免责

系统不提供:
- 医学诊断
- 伤病康复处方
- 疼痛原因判断
- 用药或补剂建议

用户报告的不适:
- 记录为 `discomfort_report` (事实)
- 建议: 暂停相关动作 + 咨询专业人员
- 不尝试诊断或给出康复方案

### 内容审核

所有进入正式计划的内容必须经过人工审核:
- 动作描述和要领
- 训练模板
- 知识库来源

`fixture=true` 的测试数据不能用于生产计划。

## 预算控制

### 硬限制

- 月度总预算: 100 RMB (可配置)
- 达到 80% 时警告
- 达到 100% 时暂停新的生成任务
- 保持记录、同步、导出功能可用

### 单次调用限制

交互式请求:
- 最多 3 次模型调用
- 最多 6 次只读工具调用
- 60 秒超时

后台计划生成:
- 1 次生成 + 1 次修复重试
- 180 秒超时

## 数据保留

### 永久保留

- 用户档案和已确认事实
- 训练记录
- 计划版本
- 知识库(已审核)

### 定期清理

- 对话文本: 90 天
- 临时媒体文件: 7 天
- 导出文件: 24 小时
- 日志: 30 天

### 用户删除

- 标记为 `deleted` 状态
- 30 天宽限期(可恢复)
- 之后物理删除
- 删除账本保留审计记录
